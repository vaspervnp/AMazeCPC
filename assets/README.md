# assets

## `sprites.png` — the sprite sheet

Paint this and `make amaze` puts it on the disc. `engine2/tools/genspr.py`
compiles it into `engine2/src/gen_spr.inc`, the rectangle lists `pip.asm`'s
`spr_draw` walks.

```
56 x 128, indexed PNG, 17 colours
one tile per sprite, side by side, no gutter:
    tile 0   SPR_MON   the monster
    tile 1   SPR_PIP   the pickup
each tile 28 px wide (7 column pairs x 4 mode-0 pixels) x 128 rows
```

**It has to be indexed, and that is not fussiness.** The game's sixteen pens
do not have sixteen distinct colours — pen 1 and pen 15 are both firmware
ink 26 (bright white), pen 0 and pen 13 are both ink 0 (black), pen 5 and
pen 12 are both ink 1. An RGB sheet could not say which of a pair you meant.
So the sheet stores **indices**: the pixel value *is* the pen number the Z80
writes, and `amaze-mode0.gpl` is that same list for GIMP.

**Index 16 is transparent** — painted magenta so it cannot be missed. It is
not a key colour that gets skipped at draw time: it becomes the *absence of a
rectangle*, which is why a silhouette is cheaper than the block it replaces.

### In GIMP 3

```bash
cp assets/amaze-mode0.gpl ~/.config/GIMP/3.0/palettes/
```

Then *Windows > Dockable Dialogs > Palettes* and refresh. Open the sheet;
it is already indexed. If you ever re-index one: *Image > Mode > Indexed*,
**Use custom palette** → `AMazeCPC mode 0`, and turn **off** *Remove unused
colours* — this palette has duplicate colours and GIMP will merge them
otherwise, which renumbers every pen. `genspr.py` checks the embedded
palette and refuses the sheet if that has happened.

### The two constraints the machine imposes

- **Four pixels across make one column pair.** A rectangle record carries
  its position and width in *pairs*, because `hud_rect` fills two bytes at a
  time — four mode-0 pixels is the narrowest thing the sprite drawer can
  place. A group of four that is not one colour is resolved by majority and
  **reported with its coordinates**, never silently averaged.
- **Rows become bands.** A band is a maximal run of identical rows, found by
  the tool rather than declared. You get 128 rows to draw in; the Z80 pays
  for the five or six the picture actually has, because every band edge is a
  multiply at draw time. 128 rows means every edge lands on an exact 2/256,
  which is the unit the band table is in.

### What it costs, and why the tool prints it

`hud_rect` costs **87 µs a call and 63 µs a row**, and almost nothing to
widen. So `genspr.py` does not minimise rectangles, it minimises
microseconds — see `engine2/tools/sprcover.py`. It prints the total, and
`pip.asm`'s `C_PIPM` / `C_PIPP` are what have to bound it:

```
SPR_MON: 6 rectangles, 4 bands, HW 1 pairs, 2754.6 us
SPR_PIP: 5 rectangles, 5 bands, HW 1 pairs, 2199.0 us
total 4953.6 us at a 28-row box
```

The hand-written rectangle lists this replaced cost **5459.2 µs** for the
identical picture.

**Widening the monster changes the game, not just the picture.** `pip.asm`
takes the aim cone from `SPR_MON_HW`, so a monster painted a pair wider is a
monster that is easier to shoot. That is why `HW` is printed.

## `amaze-mode0.gpl`

Generated by `engine2/tools/genpal.py` from `tools/world.py`'s `PEN_INK`
through `cpchw.INKS`, so the palette in GIMP and the palette the gate array
is handed cannot be two different things. The entry names are the **roles** —
"wall depth 3", "floor near" — because what matters when you are drawing a
monster is which pens are already spoken for by the scenery. A sprite drawn
in them reads as scenery.
